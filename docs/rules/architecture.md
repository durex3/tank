# 分层架构规则

基线：原始架构文档第7—10章。依赖方向：UI/Presentation → 应用与会话服务 → 战斗/配装领域 → Definitions/Core。依赖注入从app入口完成，领域不能反向引用入口。

|目录|职责|禁止|
|---|---|---|
|app|启动、路由、服务组装|伤害、移动、配装公式|
|session|离线会话组装、输入采样与模拟调度|在UI/入口复制战斗公式|
|core|时钟、ID、通用命令契约|UI、场景、设备输入|
|definitions|只读Resource定义|运行状态、HUD、HTTP|
|content|可编辑tres定义实例|运行时写回|
|loadout|配装验证、统一属性解析|UI、场景树|
|input|设备/Bot意图转PlayerCommand|扣血、计分|
|battle|权威模拟、物理适配、弹丸和伤害|原始输入、音画、账号HTTP|
|presentation|模型、镜头、特效|伤害、金币、胜负裁决|
|ui|页面、HUD、交互|复制领域公式、直接改HP|
|profile|保存、迁移、配装持久化|序列化场景树|
|network|传输、输入/快照协议|客户端裁决胜负|
|platform|安全区、生命周期、画质|战斗规则|

组合优于继承；每个组件只有一个状态所有者。TankState独立于节点。InputSource.sample输出命令，BattleSimulation验证/执行，输出会话内事件与快照。表现订阅事件，不反向修改已提交结果。

固定tick60Hz，秒数开局转tick且冷却至少1tick。伤害同tick收集、稳定排序、统一结算与死亡去重，最后裁决比赛。Godot物理不承诺跨设备锁步确定性。

Autoload最多AppServices、ProfileService、AudioService、PlatformService；按需引入，当前不创建空服务。比赛对象由SessionHost持有，退出释放订阅。禁止全局保存坦克列表和HP。

场景组合采用AppRoot/SessionHost/ScreenHost/OverlayHost/PersistentAudio。新模块先记录公开接口与依赖。新增武器使用定义+独立策略，不复制整套坦克。暂不创建未使用的联机框架或通用行为树。

架构例外写入docs/adr/NNN-标题.md，说明上下文、决定、替代方案、验证与复审条件。

005新增边界：MovementSession负责会话调度；BattleSimulation只消费世界空间PlayerCommand，TankMotor是唯一物理速度所有者。固定镜头使用16:9独立SubViewport，输入按镜头水平基映射；CameraRig不修改角色状态。灰盒地图由session组装碰撞与视觉，正式地图后续转换为资源场景。tools/check.mjs同时守卫input/battle的显式反向资源依赖和battle原始设备输入。

006新增边界：弹丸阶段只收集HitEvent，DamageResolver同tick批量结算，之后发布会话事实；视觉碰撞不能扣血。控制器交接必须更新epoch、清输入并保留武器冷却，禁止复用不同输入源的sequence空间。训练目标参数存Resource，禁止产生正式能量、奖励或比分。

007起离线暂停由session持有，冻结模拟tick和会话视觉，不全局暂停SceneTree。失焦只暂停，恢复必须显式继续；更新输入epoch、清旧请求并保留冷却，旧方向键先松开才能重新驱动。

008起视觉资产接入同时遵守docs/art/美术接入规范.md。战斗特效只消费已提交事件；尺寸、时长、预算写表现Resource，禁止影响权威碰撞/伤害/射口。原资源不覆盖，来源清单记录缺失信息，不能把PNG称为正式3D部件。

009起部件场景通过presentation/TankPartCatalog验证与装配，领域定义禁止引用视觉PackedScene。炮塔与底盘挂点遵守docs/art/009-部件接口约定.md；替换先验证后提交，不能堆积旧节点或叠加车身朝向。机库传递稳定ID，只有对应攻击策略通过验收后，才可由app创建匹配配装的新训练会话。

010起武器开发同时遵守docs/rules/010-武器与训练配装契约.md：扇形只由独立策略生成，弹组先检查总预算、禁止半组提交；连续输入取消/超时必须停火，GUI消费释放也须清除持有。配装仅开局配置，模型、属性、武器与输入模式同步，禁止局内换装绕过冷却。

011起对练遵守docs/rules/011-训练对手与生命周期契约.md：Bot只输出命令，session注入观测；双方共用武器、弹丸与批量伤害，生成弹丸前设置阵营。死亡/重建清旧输入并更新玩家epoch，保留既有弹丸身份；出生点检查碰撞，重建与保护期仅随模拟tick推进，保护期同时禁止受伤和开火。

012起离线单局遵守docs/rules/012-离线单局与结算契约.md：开局冻结规则与参赛名单，死亡按本局实体/生命去重；整tick伤害和比分提交后统一判胜，时间边界包含该tick结果。结束与暂停分离，结束不可恢复；重开由app创建新会话并先停止旧会话，UI禁止裁决比分/胜负。双车规则验证不冒充完整3v3，不发正式奖励。

013起机库美术遵守docs/art/013-MiniTanks视觉对照与机库契约.md：稳定配装ID映射静态图，属性仅展示ResolvedStats；设定图与装配模型明确区分。原素材只读，新生成资产保存提示词和来源；自动检查之外必须审阅实际渲染。Windows系统字体验收不代表Android字体与安全区通过。

014表现遵守docs/art/014-战斗视觉与镜头契约.md；视觉无权威碰撞，镜头只消费提交后位置，输入保持投影映射。

后续开发强制门槛（2026-10-12用户要求）：炮塔/底盘基础系统先于实战扩展。优先完成稀有度、解锁、等级成长、载重、技能详情与机库预览/比较/撤销/应用及持久化；验收前不得优先扩展新武器实战或3v3。开发训练全开放状态不得冒充正式解锁。设计依据为docs/炮塔与底盘类型设计.md第13—15节。

016起配装应用遵守：profile持有拥有等级和已应用ID，session服务先校验并保存候选再提交内存；失败不可改装备。草稿不落盘，试炼返回可保留预览，退出至主页丢弃。损坏存档先回退有效备份，双档无效禁止静默覆盖；JSON未来版本拒绝。能力来源固定炮塔大招/底盘被动。

017起成长使用content/growth显式等级表与PartGrowth独立定义副本；UI禁止计算成长或扣费。升级携带expected_level防重复，扣费/等级/保存同事务，失败不提交；解锁不自动装备。训练开局由app注入等级快照，局内禁止重新配装；基础定义保持只读。v1档迁移到v2，初始补给不得在v2加载时重复发放。

018起整备车间遵守：炮塔与底盘分分页展示独立部件图，整车组合预览放右侧；选择、拥有、已装备与稀有度分别表达。属性使用统一解析值、刻度条和方向正确的增减色；秒伤使用实际模拟tick冷却。底盘被动与炮塔大招分卡展示，未实现明确标记。未就绪部件可查看设计，不得应用或试炼。主界面工作流不得以目录弹窗替代；布局改动必须审阅实际渲染截图。

019起卡片状态固定：右下白圆黑勾=已应用部件，右上绿色箭头=满足升级条件，浏览边框不得冒充已装备。图集必须检查后排及滚动状态，生成图不得假定严格等分网格；隔离单块纹理防止采样相邻图。

020起详情区当前数值与对比差值独立列显示，技能卡禁止狭小内部滚动条。组合切换不可通过隐藏操作区改变预览尺寸；静态图统一画布和取景比例，原图只读。锁定卡片左上用锁图标，已拥有显示等级。详情弹窗须检查实际尺寸及底部操作可见性。

021起详情采用双栏：左侧部件身份与属性，右侧操作及技能。属性图标必须独立固定宽度，不与名称混排。技能摘要按实际文字高度排版，显式设置粗体字号，禁止缩卡片后裁字。360度旋转仅用于真实装配模型，静态设定图不能伪称可旋转；旋转只改表现状态，释放与切换必须清拖动。

022起标题页签使用独立矢量图标及统一导航底板，避免Unicode符号代替关键导航图标。升级弹窗必须有背景遮罩和明确的标题/属性/技能/费用/主次操作层级；资源需求只展示实际实现的货币。

023起右侧底部仅显示撤销、升级或详情、应用三个操作，试炼集中左侧。升级费用独立显示，升级影响单独条形提示；动作状态切换必须保持区域高度。项目数值规则不得因参考截图样式而被静默修改。

024起细进度条使用零内容边距的专用样式，禁止共享面板内边距撑大高度。禁用动作显示实际原因；黄色升级警告仅展示负面影响，正常状态保留同高占位避免预览跳变。

025起中间动作固定保留：已拥有显示升级，资格不足置灰；未拥有可解锁显示解锁，否则显示未解锁。资格由服务判断，费用和失败原因独立显示，详情保留左侧入口。此规则替代023中间升级或详情切换。

029起载重规则采用用户确认的第15节提案：炮塔重量减底盘承载为超重；超重1允许装配且最高移速降低20%，超重2及以上禁止应用与训练。LoadoutResolver统一读取content/rules/loadout.tres，UI不得复制公式。已应用组合升级后非法则拒绝整个事务，不扣费、不改等级、不保存。原15%/最多超重2约定被本条替代，最低速度比例60%仅用于解析预览，不放宽资格。

035表现采用同卡片部件图的固定锚点拼装（HangarArtCatalog/HangarCompositionStyle）；领域不依赖图片，静态图无旋转。TankView先验证全部候选，仅替换ID改变或尚未建立的模块，保持另一模块实例和旋转；装配挂点沿用009。已有3×3之外的部件后置。详见docs/art/035-部件拼装外观契约.md。
