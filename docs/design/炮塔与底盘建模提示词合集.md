# 炮塔与底盘建模提示词合集

101执行更新：七件正式部件已按用户确认的100样板统一迁移，生产目录为presentation/parts/refined_v1，精确外廓读取content/presentation/part_size.tres。下文098“尚未迁移”表述保留其编写时背景，当前执行以101记录和该Resource为准。

用途：统一风格参考图 → 独立部件与正交三视图 → Blender分组件建模 → Godot实际验收。

适用项目：Godot 4.7.2、Compatibility、世界单位米、XZ玩法平面。

## 使用约定

- 每次执行前替换提示词中的【填写项】，传入明确的参考图片和已确认的尺寸模板。
- 所有炮塔共用一套宽、高、含炮口总长；所有底盘共用另一套宽、高、含轮带总长。不同造型不能导致同类部件忽大忽小。
- 用户已确认098修正版炮塔与底盘的比例可作为后续样板。当前样板外廓为：炮塔约1.0296×0.882728×1.747688米；底盘约1.65×0.992302×1.920692米。宽度比62.4%。这些数值记录样板，不表示已完成全家族尺寸迁移。
- 当前生产尺寸仍以content/presentation/part_size.tres为唯一配置；新模板正式迁移时应统一更新配置、包装与验收，不允许逐件私设尺寸。
- 参考图或生成多视图不能证明几何一致；最终以Blender与Godot中的网格、外廓、轴心和实际渲染为准。
- 生图使用当前实际可用的imagegen工具。不要把未经核实的模型名称写成已经使用的工具。
- 以下四阶段为可复制的任务提示词，不代表全部任务已经执行。

## 1. 生成统一风格的部件设计图

```text
任务：为模块化坦克游戏设计炮塔和底盘参考图。

先分析提供的参考图片，整理造型、材质、色彩和比例，再生成设计图。

【输入】
参考图片：【填写图片路径或附件】
共同尺寸模板：【填写炮塔与底盘各自的宽、高、总长】
已确认的装配样板：【填写参考路径】

【美术方向】
采用精致的风格化3D游戏模型效果：
- 造型紧凑、厚实，具有清晰的机械结构。
- 大块装甲、适度倒角，避免密集碎小细节。
- 象牙白哑光装甲、深灰机械结构、黑色橡胶、少量黄色点缀。
- 金属与橡胶材质区分明确，避免塑料般油亮。
- 不使用像素美术，不使用写实战损、密集划痕或脏污。
- 画面应接近Godot实时渲染能够实现的效果，不依靠复杂后期掩盖模型结构。

【模块化规则】
1. 所有炮塔使用同一套宽、高、总长，包含炮口、底座和全部附件。
2. 所有底盘使用另一套统一宽、高、总长，包含轮胎、履带和挡泥板。
3. 不同部件通过轮廓、结构和材质分区体现区别，不能通过放大或缩小体现等级、载重或稀有度。
4. 任意炮塔与任意底盘组合后，都应比例协调。
5. 以已经确认的整车样板为比例基准：底盘应有足够的承托感，炮塔不能压过底盘。
6. 炮塔安装底座与底盘安装座使用统一接口，不允许出现细长支柱、大面积悬空或明显穿插。
7. 不允许为了满足尺寸而把圆形轮胎、炮口或轴承非等比拉伸。

【本次设计对象】
部件名称：【填写】
功能与关键外形：【填写】
活动结构与数量：【填写】

例如：
速射机炮：左右两根独立炮管，低矮安装座，紧凑装甲壳体。
侦察轮式底盘：四个完整车轮，清晰轮间距，独立挡泥板和中央炮塔安装座。

【输出】
生成一张清晰的三分之四视角设计图。
使用正交相机，朝向和俯视角与整套部件参考一致。
背景为纯暗紫色，无文字、尺寸线、展示台、场景或其他部件。
完整展示主体，不裁切，不使用广角透视。
保存提示词、参考来源和原始输出。
```

## 2. 分析部件，生成独立提取提示词

```text
任务：分析提供的坦克设计图，为炮塔与底盘建立可用于Blender建模的参考资料。

输入图片：【填写】
共同尺寸模板：【填写】

先列出图中全部独立模块与机械组件，再输出Markdown格式的提示词合集。

【模块与机械组件要区分】
模块是可替换的整个炮塔或整个底盘。
机械组件是模块内部需要独立建模或运动的部分。

炮塔组件通常包括：
- 装甲壳体
- 安装底座
- 炮管与炮口
- 后坐套筒
- 储罐、软管或其他功能附件

底盘组件通常包括：
- 车体装甲
- 炮塔安装座
- 挡泥板
- 独立车轮及轮毂
- 悬挂与轮轴
- 左右履带及内部轮组

不要把贴图上的线条自动判断为实际结构。
无法从参考图确定的背面或内部结构，需要明确标记为设计补全。

【每个模块输出四条独立提示词】
1. 原图视角的独立提取图
2. 正交正视图
3. 正交右侧视图
4. 正交顶视图

【每条提示词必须独立包含】
- 模块名称与完整外形描述。
- 材质、配色、关键结构及组件数量。
- 指定观察方向。
- 同类模块的统一尺寸要求及具体模板数值。
- 纯暗紫色背景。
- 完整补全遮挡部分，不能只保留可见表面。
- 不得新增炮管、车轮、储罐或其他结构。
- 无文字、标注、尺寸线、背景投影和其他物体。

每条提示词均为独立传入，不能用“同上”“保持前述要求”等总括语句省略约束。
可以明确引用随该次调用附带的参考图，但不能假定该调用能看到此前对话。

【三视图必须逐条明确】
使用严格正交投影，无透视缩短、无消失点、无镜头畸变。
正视图只展示正面，不能看到侧面或顶面。
右侧视图只展示模型自身右侧，不能看到正面或顶面。
顶视图垂直向下，不能看到侧壁。
平行结构在图中必须保持平行。
三个视图必须对应同一件物体，不允许各自重新设计。

【尺度要求】
同类模块使用固定画布与相同单位像素比例。
不同视图根据真实宽高长保持对应关系，不能每张图各自放大到铺满画布。
生成图片只作为建模参考，尺寸最终由Blender中的数值与外廓测量保证。

输出文件名：炮塔与底盘生图提示词合集.md
```

## 3. 提取独立参考与三视图

```text
任务：根据《炮塔与底盘生图提示词合集.md》生成对应模块参考图。

每次处理一个完整模块，先完成一个炮塔和一个底盘样板，再扩展其他模块。

【执行顺序】
1. 从设计图生成该模块的独立原视角图。
2. 检查独立图与原设计的轮廓、比例、材质和组件数量。
3. 以这张独立图为共同参考，生成正交正视图。
4. 以同一独立图及已通过检查的视图为参考，生成正交右侧视图。
5. 以同一套参考生成正交顶视图。
6. 对四张图进行交叉检查，不一致时修正对应视图。

【重点检查】
- 双管机炮必须始终只有两根炮管，位置、间距和直径一致。
- 四轮底盘必须具有四个完整车轮，轴距、轮距和直径一致。
- 左右履带应完整闭合，不能悬空或断裂。
- 安装底座的位置和尺寸必须在各视图中一致。
- 正视图的宽度应与顶视图宽度对应。
- 侧视图的长度应与顶视图长度对应。
- 正视图与侧视图的高度必须对应。
- 三视图必须严格正交，没有透视缩短或角度歪斜。
- 所有视图保持同一套结构，不能把生成偏差当成新设计。

【遮挡补全】
补齐背面、底面和被遮挡结构。
补全必须遵循已有结构，不得随意添加炮口、排气孔或装饰。
有歧义的部分先记录，再通过结构设计解决；必要时补充背视图。

背景统一纯暗紫色。
保留原始输出、提示词、参考来源和修订记录。
正交效果需要检查，不能仅凭提示词认定已经符合要求。

【批量协作】
如果用户明确要求并行，可按当前环境的实际并发上限分批执行。
每个执行者负责一个完整模块的四张图，模块内部按上述顺序执行。
每个执行者收到完整独立提示词、实际参考图和共同尺寸模板。
不允许不同执行者自行改变比例、材质或机械结构。
```

## 4. 用Blender建模炮塔和底盘

```text
任务：依据已确认的参考图和三视图，在Blender中制作可用于Godot的模块化坦克部件。

【输入】
本次对象：【填写部件名称与类型：炮塔 / 底盘】
参考图和三视图：【填写路径】
共同尺寸模板：【填写已确认数值及配置来源】
活动组件与数量：【填写】

【尺寸与坐标】
1. 单位使用米，导出Godot后Y向上、-Z为正前方。Blender工作坐标与glTF导出坐标之间的转换须验证，不能重复旋转。
2. 使用项目确认的共同尺寸模板：
   - 所有炮塔必须具有相同宽、高、含炮口总长。
   - 所有底盘必须具有相同宽、高、含轮带总长。
3. 所有可见附件都必须计入静止外廓。
4. 不允许逐件自行决定最终尺寸。
5. 不能通过整件非等比缩放满足尺寸；应修改组件尺寸和布局。
6. 当前认可样板的尺度作为新模板制定依据，不能擅自改写生产配置。

【建模要求】
1. 尽可能还原参考图的轮廓、比例和材质分区。
2. 每个完整模块以6000 tris为优化参考，包含全部机械组件与附件；用户于2026-10-15明确允许超过6000，不再作为硬性上限，也不强制整车12000上限。优先保留轮廓、轮胎及机械细节，按应用修改器并三角化后的最终导出几何分别统计，记录实际面数；移动端性能仍须真机验收。
3. 合理分配面数，优先保证轮廓、炮口和圆轮；微小细节通过材质表现。
4. 布线清晰、有序，避免无意义的密集三角面。
5. 外露装甲边缘适度倒角，避免薄纸边缘和过度圆润。
6. 支持360度观察，背面与底部必须完整。
7. 炮口具有真实内壁和适当深度，不能只是黑色圆形贴图。
8. 轮胎必须具有真实厚度、完整内外侧和正确圆度。
9. 不得存在意外孔洞、悬空组件、明显穿模、重合面或闪烁。
10. 正常机械装配的嵌合与间隙应有依据，不能用互相穿插掩盖结构缺失。

【机械拆分】
炮塔：
- 壳体、安装底座与活动炮管分别建模。
- 双管机炮的左右炮管必须独立，能够分别沿炮管轴后坐。
- 后坐时不能拉伸壳体、炮口或附件。
- 炮塔旋转轴与共同安装轴重合。

轮式底盘：
- 车体与四个车轮分别建模。
- 每个车轮原点位于真实轮轴中心。
- 左右轮保持同径，转动时不偏心、不摆动。
- 前轮转向与车轮滚动使用不同层级的轴心。

履带底盘：
- 左右履带机构分别组织。
- 轮组、带体和需要运动的履带片明确分离。
- 履带路径闭合，与轮组正确接触，不能断裂或穿过车体。

【材质与UV】
- 象牙白哑光装甲、深灰机械件、黑色橡胶、少量黄色点缀。
- 各部件使用统一材质体系和纹素密度。
- 优先使用可复用材质与合理UV。
- 基础色不要烘焙强烈方向光、高光或投影。
- 法线贴图应来自正确的高低模烘焙或可验证的程序化结构。
- 不把生图生成的彩色凹凸图直接当成正确法线贴图。
- 避免可见接缝、明显重复、纹理拉伸和不同部件清晰度差异。
- 生图材质只能作为候选，必须检查UV映射、PBR通道和实际渲染。

【Godot装配】
- 最外层根节点保持单位变换。
- 保持项目既有Muzzle和TurretSocket权威挂点，不移动碰撞或伤害射口来迁就美术。
- 视觉炮口与权威射口分别处理。
- 所有模型调整放在表现几何层。
- 不修改原始模型，保存新的派生版本。
- 资源定义保持只读；动画状态、材质实例和生命周期清理沿用项目规则。

【执行流程】
1. 分析参考图，记录可确认结构与需要补全的结构。
2. 建立共同尺寸外廓盒与安装轴。
3. 先用简单几何完成炮塔＋底盘装配，确认大小关系。
4. 分组件建模，先主轮廓，再机械结构，最后细节。
5. 检查圆度、厚度、轴心、间隙和活动范围。
6. 完成UV与材质。
7. 渲染正面、背面、左右侧、顶面、底面和三分之四视角。
8. 与参考逐项比较，修正比例、轮廓和结构。
9. 在Godot Compatibility渲染器中检查近景、游戏正常尺寸和连续动作。
10. 检查通过后交付.blend、GLB、贴图、尺寸报告、三角面统计和验收截图。

没有实际完成的检查必须标记“待验收”。
不能把效果图漂亮、GLB导出成功或自动检查通过，等同于模型已经完成。
桌面检查不替代Android触屏、性能、热稳定或真机验收。
```
