# 011-离线训练对手与玩家受伤重建

日期：2026-10-11。状态：实现、13项自动检查与Windows Compatibility视觉检查完成；Android待验收。

## 目标与行为

训练页面默认保留无对手练靶；点击Start sparring后生成一名轻履带主炮对手，在中央通道巡逻，有视线且进入射程时瞄准开火。玩家和对手使用同一伤害链路，阵营过滤阻止自伤。双方同tick命中可互相击毁。

死亡停止移动和开火、移除车体阻挡并隐藏模型，180tick后尝试安全重建；出生位置被占用时尝试两个侧方位置，均不安全则延后。重建恢复本配装满血并递增life，保护60tick；保护期同时禁止受伤和攻击。暂停冻结全部模拟计时。死亡和重建清除旧输入，玩家更新控制epoch；已生成弹丸保留原阵营继续飞行。训练不发奖励、不计算正式胜负。

## 分层与接口

- definitions/SparringRules及content/training/sparring.tres：巡逻点、速度比例、请求间隔、重建和保护时长，只读调参。
- input/TrainingBotInput.sample：只接收tick、位置、存活、可见性和射程值，输出PlayerCommand；不引用战斗节点、不扣血。有限状态为INACTIVE、PATROL、ENGAGE。
- session/SparringSession：组装对手、采样墙体视线、提交下一tick命令；MovementSession提供start_sparring入口，检查首次出生安全并管理玩家生命周期输入。
- battle/WeaponAttack.execute：提取玩家/对手共用攻击执行；ProjectileSystem在初始射口扫掠前写入team_id。BattleSimulation分别执行双方攻击后统一推进弹丸、批量结算伤害，再发布事实。
- battle/TrainingLives：持有重建与保护计时；safe_spawn统一首次出生和重建检查。TankActor使用DamageableState/Hurtbox接入原伤害系统。
- presentation/TankHealthView：消费事件显示血量、保护及重建状态；CombatView按阵营区分弹丸颜色。UI只发起对练与显示状态，不裁决伤害或AI。

执行Godot --path . --script res://tools/capture_sparring.gd：SPARRING CAPTURE: PASS。通过真实StartSparring按钮触发流程，生成并人工查看artifacts/sparring-damage.png、sparring-player-down.png、sparring-rebuild.png。修正重建后残留死亡提示，重新运行全部13项检查及截图；重建页面正确显示满血、保护和武器锁定。

渲染使用Compatibility / NVIDIA RTX 3060 Laptop GPU。环境出现已知系统CA证书库读取错误；自动检查仅对该精确环境错误分类，其余ERROR导致失败。本记录不代表网络或Android验收。

## 美术、工具与限制

使用game-ai、godot-gdscript、godot-physics技能；通过Node REPL MCP读写工程、启动本地Godot及查看截图。复用现有六个模块化部件基础模型和炮口/命中/爆炸贴图，无新增生图。模型仍为基础视觉，未宣称最终美术完成。

当前对手只适用预设中央巡逻通道，没有全地图寻路、脱困或团队战术。没有正式计分、时间限制、胜负结算、技能、被动或完整3v3比赛。Android多指、安全区、后台、导出、性能和真机体验待验收。下一批优先建立离线单局计时/比分/结束与重开契约。
