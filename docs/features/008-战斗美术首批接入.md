# 008-战斗美术首批接入

状态：实现、10项Windows自动检查及Compatibility截图检查完成；Android待验收。

## 目标与分层
复用assets/effects现有炮口、冲击波、爆炸透明贴图，替换战斗占位闪光。presentation消费已提交战斗事实；没有修改伤害、碰撞、射速或射口，也没有制作正式坦克模型。本批使用create-game-assets、godot-gdscript技能及Node REPL MCP读写工程、运行本地Godot；未生成新图。

## 接口与变更文件
- presentation/combat_effect_style.gd：只读Resource，配置三类Texture2D、米制宽度、持续时间、32个同时显示上限及相机偏移。
- content/presentation/default_vfx.tres：绑定原有muzzle-v1/shockwave-v1/explosion-v1。
- presentation/combat_view.gd：on_event映射weapon_fired/projectile_hit/entity_died至Sprite3D；扩张、淡出、销毁，暂停继续均跟随会话。结束Tween立即从登记中移除；超限仅丢弃视觉。
- tests/presentation/combat_view_tests.gd及tools/check.mjs：增加尺寸/透明度、拒绝开火无特效、事件纹理选择、预算回收、缩放/透明度暂停、退出释放检查。
- tools/capture_art.gd：渲染第一帧美术预览，先等待视口稳定。截图注入三个已提交事件用于展示，是视觉样例，不是击杀流程证据；实际开火/伤害链路由combat tests回归。
- docs/art/美术接入规范.md、combat-asset-manifest.json：记录技术规格、来源缺口和底盘/炮塔制作接口目标。原assets与原来源文件保持不变。
