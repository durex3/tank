# 018-整备车间分页与部件属性交互

日期：2026-10-12。状态：桌面实现与检查完成；Android待验收。

## 目标与结果

根据用户提供的MiniTanks截图重做整备主界面的信息层级。炮塔、底盘独立分页，左侧四列部件卡片与下方属性面板，右侧整车预览、载重和撤销/解锁升级/应用/试炼操作。保留独立设计，不复制参考游戏数值。

22炮塔与10底盘均有独立图标、稀有度、拥有/待开发标记；支持全部、已拥有、可升级与名称/ID搜索。选中与已装备分别展示。属性以图标、刻度条、数值及红绿差值展示；底盘被动和炮塔大招独立展示，完整描述可打开详情。

## 分层与接口

ui/screens/hangar_screen.gd组装页面与草稿；HangarDirectory发出part_selected，HangarPartCard只显示卡片；HangarDetailsPanel消费解析结果，HangarStatRow负责数值绘制，StatTicks只画刻度。EquipmentService继续持有升级/解锁事务，UI不计算成长或扣费。ResolvedStats.nominal_dps按实际模拟tick计算秒伤。

PartEntry新增基础、技能、定位摘要，由content/parts/catalog.tres提供。HangarPartArtCatalog以稳定ID映射AtlasTexture，PartIconFrames保存图框，领域不引用图片。

## 美术

使用godot-ui-control与imagegen技能，Node REPL MCP执行本地Godot；image_gen生成22个独立炮塔和10个独立底盘图集。来源和完整提示词见assets/generated/parts/provenance.json，图框见frames.json。Godot测量两图集角点alpha为0；按alpha边界取图框，不修改原像素。用户原始assets未覆盖。右侧设定图与装配模型明确区分，PNG不代表新增3D模型。

## 验收

node tools/check.mjs：21项全部PASS，包含32项目录分页、独立图集、搜索/拥有过滤、待开发禁用、属性比较及tick秒伤回归。成长测试通过主界面升级按钮，确认300→280金币、主炮Lv1→2、伤害124及存档。

Godot运行tools/capture_hangar_workbench.gd生成实际截图并人工审阅：artifacts/workbench-turrets.png、artifacts/workbench-chassis.png。1280×720两页无主要区域溢出，卡片图与整车预览分别展示，红绿差值与操作区可见。

## 限制与后续

32项目录和图标齐全不代表32项战斗实现。当前仍只有3炮塔、3底盘基础玩法，全部大招/被动明确待实现。初始300金币无试炼收益。载重仍沿用已实现规则，未将设计提案静默替换为新战斗公式。Android字体、安全区及真机验收未完成；炮塔底盘基础优先于实战扩展。
